# Nano4 GP1 生醫 HPC 課程規劃（講師版）

> 對象：授課講師與助教
> 計畫：`GOV115088`（國網生技醫藥高效能運算推廣與應用計畫），CPU-only，所有 Slurm 作業使用 `ngs62g`，每個作業固定 `-c 8 --mem=62G`
> 線上講義：<https://gemini960114.github.io/Nano4-Docs/>

## 1. 課程總覽

| 場次 | 章節 | 時間 | 學員結束時能做到 |
| :--- | :--- | :---: | :--- |
| **第一堂（基礎）** | 第 01 章 登入、2FA 與環境管理<br>第 02 章 VS Code Remote-SSH 與 AI 工具鏈 | 3 小時 | 用 VS Code / Antigravity 連上 Nano4（透過 ssh-proxy 只認證一次），分清楚 `$HOME` 與 `/work`，會載入生醫模組，送出第一個 Slurm 作業 |
| **第二堂（基礎）** | 第 03 章 Slurm 語法與作業調度<br>第 04 章 AI 輔助生醫質控管線 | 3 小時 | 寫出並送出標準、陣列、相依作業，並自己改寫陣列作業處理樣本；用 `seff` 檢查資源；跑 FastQC / MultiQC 並讀懂報告；用 Apptainer 容器在計算節點執行 MultiQC |
| **進階課** | 第 05 章 AI Agent 自動化 Slurm 排程<br>第 06 章 AI Agent 技能總匯庫<br>第 07 章 nf-core/ampliseq 真實 16S 案例 | 3 小時 | 讓 AI Agent 把流程改寫成 Slurm 作業、用 Skill 抓出不合規的腳本，並完成一次 nf-core/ampliseq 官方測試 |

設計原則：

- 第一堂只做環境與連線。初學者最容易卡在 2FA、VS Code 連線與 ssh-proxy，保留足夠的除錯時間。
- 第二堂從 Slurm 基礎到自己改腳本，再以 FASTQ 質控與容器收尾：同一份資料先用模組跑、再用容器跑，自然銜接進階課的 nf-core。
- 第 07 章的 pipeline 需要長時間執行（官方測試實測約 28 分鐘），獨立成進階課，並在課程一開始就送出作業。

## 6. 資源容量與排隊注意事項

`ngs62g` 共有 13 個節點（`25a-cpn[01-10,16-18]`）、1,664 個核心。以 2026-09-23 晚間的空閒量（約 1,600 核心）估算，整個分區大約可同時執行 **200 個** 8 核心作業；每位使用者最多 120 個作業。以下以第一班 **20 位學員**估算：

| 練習 | 每位學員同時作業數 | 20 位學員合計 | 評估 |
| :--- | :---: | :---: | :--- |
| 第 01 章練習 5、第 03 章 Lab 2 | 1 | 20 | 沒問題 |
| 第 03 章 Lab 4 陣列作業（`%4`） | 4 | 80 | 沒問題 |
| 第 03 章 Lab 8 陣列作業（`1-4`） | 4 | 80 | 沒問題 |
| 第 03 章 Lab 6 `salloc` | 1 | 20 | 沒問題；提醒用完 `exit` |
| 第 03 章 Lab 9 容器 | 1 | 20 | 運算沒問題；注意 Docker Hub 下載次數（見 §4「Lab 9 下載限制」） |
| 第 05 章 Case A / B | 1 | 20 | 沒問題 |
| 第 07 章官方測試（`queueSize = 5`） | 1 + 5 | 約 120 | 沒問題 |

建議：

- `07-nfcore-ampliseq-case-study/config/nano4.config` 的 `executor.queueSize` 已由 10 調為 5，實測官方測試時間不變（約 28 分鐘）。學員超過 30 人時，可再調低（例如 3），但官方測試會跑得更久。
- 第 07 章 §3.4 真實資料不要全班同時執行，改用講師事先跑好、放在 [GitHub Release `ampliseq-demo-2026-09-23`](https://github.com/gemini960114/Nano4-Docs/releases/tag/ampliseq-demo-2026-09-23) 的示範結果。
